= Language and ecosystem audit
:toc:

== Finding

Svalinn was not ported *from* AffineScript to TypeScript. This checkout contains
an AffineScript tree under `src/` and `ui/src/`, but those files are generated,
incomplete migration artifacts, not a verified or runnable implementation. The
working gateway is a separate MVP implementation at
`tools/mvp/svalinn_gateway.ts` (run with Deno). It was kept as a temporary
working surface while the AffineScript migration was incomplete. The repository
explicitly grandfathered it in `.claude/CLAUDE.md`; that carve-out conflicts
with an absolute TypeScript ban and is migration debt, not evidence that
TypeScript is suitable or approved for production.

This checkout does not contain the history needed to identify the original
author or decision that introduced the MVP: its Git history is shallow and
contains only the current baseline commit. The available evidence supports the
above technical explanation, not a more specific historical claim.

== Cross-project scope and limitation

The integration metadata names Vörðr, Rokur, Cerro Torre, Selur, and Stapeln.
They are separate repositories and are not checked out in this workspace. In
this environment, both `gh repo view` and `git ls-remote` returned “Repository
not found” for `hyperpolymath/{vordr,rokur,cerro-torre,selur,stapeln}`. Therefore
this audit does *not* claim to have inspected their source trees or removed
anything from them. It only inspected Svalinn's checked-in links, contracts,
configuration, and integration references. The URLs/owners or access for the
linked repos must be corrected before a cross-repository language audit can be
completed.

== Conflicting target decisions

The repository's records do not fully agree:

* `.claude/CLAUDE.md` now follows the recorded D3 handoff: Ephapax is the
  conditional target, and the TypeScript gateway is legacy debt.
* `docs/ephapax-migration/HANDOFF.adoc` records Decision D3 as ReScript →
  Ephapax, with a readiness spike required before any port; it explicitly says
  AffineScript is not the target.
* `STATUS.md` still calls for an AffineScript compiler spike and describes
  AffineScript as the migration question.

The D3 handoff says to stop if its readiness spike is not green. Resolve the
stale STATUS.md direction against that decision before any full rewrite. No
cross-project or production migration should be inferred from the partial
`.affine` files.
